How the escrow works

Client deposits dUSD into the on-chain escrow PDA (seeded by depositor + a fresh nonce per deposit — one wallet can hold many concurrent verifications). The oracle verifies → YES/NO marks the escrow claimable (operator claims); UNDECIDED marks it refundable (the depositor refunds). The server never holds a private key — every movement is signed in a wallet.

Attestation is required. After the deposit lands, the client submits an attest instruction writing the deposit transaction's signature into the escrow account (a program cannot see its own transaction's signature during execution). The server refuses verification — and the dashboard hides Claim — for unattested deposits. The depositor's refund works regardless.
